# UMEC AI Planner

Self-hosted семейный AI-планировщик, который связывает почту, календарь, задачи, таймеры и голосовые команды в одном приватном пространстве.

[Сайт и инструкция](https://tigramaan.github.io/ai-planner/) · [Быстрый запуск](#быстрый-запуск) · [Skill для агента](skills/deploy-aiplanner/SKILL.md) · [Security](docs/THREAT_MODEL.md)

## Зачем он нужен

Обычные приложения хорошо показывают отдельные списки. AI Planner помогает выполнить действие между ними: найти письмо, понять обязательство, создать задачу, подобрать время, подготовить ответ и безопасно провести изменение через подтверждение.

### Контур обязательств

Отдельный раздел проверяет последние 30 дней почты и сопоставляет найденные договорённости с открытыми задачами и календарём:

- **Я обещал:** обязательства и сроки, которые пользователь взял на себя;
- **Ждут от меня:** вопросы и просьбы, где нужен следующий шаг;
- **Жду я:** отправленные запросы, по которым ожидается действие другого человека;
- **Нет в плане:** обязательства, которым не соответствует задача или время в календаре.

Анализ запускается только по явной команде, ограничен 15 входящими и 15 отправленными письмами и выполняется с `store=false`. Кнопка «Разобрать» лишь подготавливает команду. Она ничего не отправляет и не создаёт автоматически.

### Почта и документы

- поиск Gmail и Outlook естественными фразами: по отправителю, дате, непрочитанности и вложениям;
- отбор писем, которые требуют ответа, с исключением рассылок и автоматического шума;
- резюме письма и до пяти вложений PDF, DOCX, XLSX, CSV, HTML или TXT;
- подготовка полного письма по цели пользователя;
- обязательный предварительный просмотр адресата, темы и текста перед отправкой.

### Календарь, задачи и таймеры

- единые экраны «Сегодня» и «Неделя» для локальных задач и Google/Microsoft календарей;
- создание, перенос, изменение участников и отмена встреч через подтверждаемое действие;
- Google Meet, Microsoft Teams, Zoom и постоянные комнаты Телемоста;
- задачи со сроками, описанием, приоритетом, поиском, фильтрами и архивом;
- именованные таймеры с живым обратным отсчётом в чате.

### Уведомления и PWA

Приложение устанавливается на iPhone, Android и desktop как PWA. Таймер или задача со сроком создаёт одно Web Push напоминание. Доставка учитывается отдельно для каждого браузера: успешная отправка на Windows не скрывает ошибку iPhone, устаревшие подписки удаляются после ответа `404/410`, а тест в настройках проверяет именно текущее устройство. Принятие сообщения push-сервисом не выдаётся за подтверждение показа операционной системой.

### Приватность и контроль

- отдельные аккаунты, задачи, история, настройки и OAuth-токены для каждого участника;
- токены интеграций зашифрованы AES-256-GCM;
- модель не получает OAuth-токены и серверные секреты;
- внешние отправки и изменения проходят immutable pending action и явное подтверждение;
- одноразовые семейные приглашения, HttpOnly cookies, аудит и защита от BOLA;
- сервисы запускаются в собственных контейнерах без root-доступа.

## Быстрый запуск

Требуются Linux-сервер, Docker Compose, домен с DNS-записью на сервер и открытые порты 80/443.

```bash
git clone https://github.com/tigramaan/ai-planner.git
cd ai-planner
cp .env.example .env
mkdir -p .secrets
openssl rand -base64 32 > .secrets/vapid_private.pem
docker compose --profile caddy up -d --build
docker compose ps
```

Перед запуском замените все `replace-with-*` в `.env`. Генерируйте секреты локально:

```bash
openssl rand -hex 32                         # JWT_SECRET / WORKER_SERVICE_TOKEN
openssl rand -base64 32                      # SECRET_MASTER_KEY
openssl rand -base64 24                      # POSTGRES_PASSWORD
```

Никогда не публикуйте `.env`, OAuth client secrets, private keys, backup-файлы или реальные токены. `.gitignore` уже исключает их.

## Подключения

| Сервис | Что подготовить | Callback |
|---|---|---|
| OpenAI | API key и лимит расходов | не требуется |
| Google | OAuth Web client; Calendar, People, Gmail API | `/api/v1/integrations/google/oauth/callback` |
| Microsoft | Entra Web app и delegated permissions | `/api/v1/integrations/microsoft/oauth/callback` |
| Zoom | General App OAuth | `/api/v1/integrations/zoom/oauth/callback` |
| Яндекс 360 | service app для организации; CalDAV/IMAP/SMTP | зависит от организации |

Подробная схема возможностей и пошаговая настройка находятся на [GitHub Pages](https://tigramaan.github.io/ai-planner/#install) и в [справочнике skill](skills/deploy-aiplanner/references/providers.md).

## Установка через AI-агента

Передайте Codex или Claude Code репозиторий и попросите использовать `skills/deploy-aiplanner/SKILL.md`. Навык проверит сервер, поможет создать `.env`, по одному запросит provider credentials, запустит Compose и выполнит smoke/security checks. Агент не должен печатать или коммитить секреты.

Claude Code здесь поддерживается как агент установки и разработки. Runtime-команды планировщика сейчас обрабатывает OpenAI Responses API. Поддержка Anthropic Claude как runtime-provider — хороший отдельный contribution.

## Архитектура

```text
Browser / PWA → Web (Next.js) → API (FastAPI) → PostgreSQL
                                  ↓              Redis → Worker → Web Push
                         Google / Microsoft / Zoom
```

Токены интеграций зашифрованы AES-256-GCM; внешние действия проходят immutable pending action и явное подтверждение; сервисы запускаются non-root. Контракты и требования находятся в `contracts/` и `specs/`.

## Проверка

```bash
.venv/bin/ruff check services/api
.venv/bin/pytest services/api
npm run worker:test
npm run web:test
npm run web:build
node tools/guards/check-file-lines.mjs
```

История репозитория проверяется Gitleaks. Запустите локально:

```bash
docker run --rm -v "$PWD:/repo" zricethezav/gitleaks:latest git /repo --redact
```

## Хотите помочь?

Проект открыт для contributors. Особенно нужны:

- runtime-provider для Anthropic Claude;
- Ollama и другие OpenAI-compatible локальные модели;
- YandexGPT и навык Алисы;
- GigaChat и голосовые ассистенты Сбера;
- новые календарные/почтовые коннекторы;
- мобильное тестирование, локализация и accessibility.

Откройте issue с предложением, затем небольшой PR с тестами и обновлением спецификаций. Если хочется «довайбкодить» свой provider — берите существующий adapter как контрактный пример и не передавайте модели OAuth-токены или пользовательские секреты.
